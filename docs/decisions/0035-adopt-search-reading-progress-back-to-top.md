# 0035. 検索・読了バー・トップへ戻るボタンを採用する(追認記録)

- 状態: 採用(ADR 0008「スコープ外」の読了バー・トップへ戻るボタン・検索ボックスを採用する)
- 日付: 2026-11-19
- 関連 PR: #124(読了バーとトップへ戻るボタン)・#125(Pagefind による全文検索)。どちらも 2026-07-18 にマージ。本 ADR はその決定を後から記録する
- 関連 ADR: [`0001`](0001-initial-stack-and-mirror-brand.md)(便利機能は必要になった時点で個別 PR で移植する) / [`0008`](0008-layout-skeleton-with-sticky-header-mobile-menu-multicol-footer-and-rss.md)(3 つをスコープ外に置いた)

## 背景

ADR 0001 は、全文検索などの便利機能を立ち上げ時には採用せず、必要になった時点で個別 PR で姉妹サイトから
移植すると決めた。

ADR 0008 は「スコープ外」の節で、次の 3 つを理由を付けて外した。

| 機能 | 0008 が外した理由 |
|---|---|
| 読了バー(Reading Progress) | 法令詳細は中尺で不要 |
| トップへ戻るボタン | sticky Header の Home リンクで代替できる |
| 検索ボックス(Pagefind 等) | 7 法令の規模では nav から直接たどれば足りる |

2026-07-18 に #124 と #125 がこの 3 つを入れた。どちらも、姉妹サイト(edu-evidence・edu-watch)にあって
このサイトだけに無い非対称をなくす、ファミリーの UI 統一として入れている。#125 は ADR 0001 の手順どおりの
移植にあたる。一方で、0008 が付けた理由の前提が崩れたことは、どの ADR にも書かれていない。

その時点で、法令は 7 から 12 に、ガイドは 11 本になっており(#124 の本文)、検索の索引は 30 ページだった
(#125 の実測)。0008 を書いたときは 10 ページ・7 法令だった(0008 の背景)。

## 検討した選択肢

1. **本 ADR を書かない** — 下の「反対意見」
2. **0008 を撤回して書き直す** — 却下。0008 の決定(Header・Footer・メタタグ・RSS)はそのまま有効で、
   変わったのはスコープ外の 3 項目だけ
3. **追認の ADR を起こし、0008 の状態行に注記する** — 採用

## 決定

ファミリーの UI 統一のため、次の 3 つを姉妹サイトのミラーで採用する(#124・#125 の実装を追認する)。

- **読了バー**: 長文のページ(法令詳細とガイド)にだけ出す。`Layout.astro` の `longForm` で切り替える
- **トップへ戻るボタン**: 全ページに置く
- **全文検索**: Pagefind。`/search` のページと、ヘッダー(デスクトップの検索アイコン・モバイルメニューの検索欄)からの導線

0008 がスコープ外に置いた用語ツールチップは、引き続き採用しない(法令の用語を独自に定義しない ADR 0002 の
立場は変わらない)。

## 帰結

- 0008 だけを読んで「3 つとも採用していない」と読む誤りがなくなる
- 検索が「置いてある」だけで「引ける」ことを保証しない点は、`e2e/search.spec.ts` が見ている
  (索引の生成が飛んでも、入力欄を描いたまま 0 件を返すだけになるため)
- 3 つとも姉妹サイトのミラーなので、姉妹サイト側を変えたら追随が要る

### 反対意見

**「スコープ外」は決定ではないので、覆す ADR は要らない。** 0008 の「スコープ外」は「この ADR では扱わない」
という範囲の宣言で、採用しないと決めたわけではない、という読み方がある。ADR 0001 も、必要になれば個別 PR で
移植すると決めている。

それでも本 ADR を書くのは、0008 が 3 つそれぞれに採用しない理由を書いているため。0008 だけを読めば
「採用しない」と読めるし、その理由の前提(7 法令・中尺)が崩れたことを書いておかないと、次に同じ判断を
する人が根拠をたどれない。#124・#125 の時点で ADR を起こさなかった事実も、追認記録としてここに残す。

## 撤回 / 再検討の条件

- ファミリーの UI 統一の方針をやめ、このサイト独自の UI に分ける場合
- 検索の索引の大きさや Pagefind の配信が、静的配信の制約(ファイル数・サイズ)に当たるようになった場合
