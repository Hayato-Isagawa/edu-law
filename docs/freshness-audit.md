# 公式文書バージョン棚卸し(freshness audit)

法令ページが参照する公式文書(公式解説 PDF / HTML・通知・ガイドライン)が現行版のままかを定期的に棚卸しする運用手順。`lastVerified` の 90 日サイクル(ADR 0002 / 0003)に乗せて、実質四半期ごとに回す。

## 目的と位置づけ

鮮度管理は 3 層で構成する。本手順はその第 3 層にあたる。

| 層 | 仕組み | 捕捉できるもの | 捕捉できないもの |
|---|---|---|---|
| 1 | `link-check.yml`(lychee・週次) | 404 などのリンク切れ | 旧 URL が 200 のまま生存するケース |
| 2 | `stale-check.yml`(週次) | `lastVerified` の 90 日超過(再検証リマインダー) | 実際に新版が出たかどうか |
| 3 | 本手順(棚卸し) | **「旧 URL 生存のまま新版公開」= 静かな改訂**・301 移転 | — |

### 実証例(2026 年 6 月)

- **いじめ重大事態調査ガイドライン**: 令和 6 年 8 月改訂版が公開されても、ページが参照していた平成 29 年通知 URL は 200 のまま生存。lychee では検知できず、棚卸しで発見した(PR #82)
- **学校保健の公式解説 URL**: 301 リダイレクトに移行(lychee は `--accept` で 301 を許容しているため通過)。棚卸しで発見した(PR #82)
- 対照例 — **児童虐待対応の手引き**: 令和 8 年 5 月改訂版への更新で旧 PDF が 404 になったケース。これは第 1 層(lychee)が検知できた(issue #78 → PR #80)

## トリガー

- `stale-check.yml` が自動起票する `[auto] stale-check: <slug>` issue(`lastVerified` 90 日超過)
- 複数法令の issue が同時期に立った場合は、1 回の作業でまとめて棚卸しする。`lastVerified` は棚卸しのたびにほぼ同時期へ更新されるため、以後は自然に四半期サイクルで揃う

## 手順

### 1. 対象の確定

open の `stale-check` ラベル付き issue を一覧し、対象 slug を確定する。

```bash
gh issue list --label stale-check --state open
```

### 2. 棚卸し(法令ごとに独立して実施・並列化可)

対象の `src/content/laws/<slug>.md` ごとに以下を確認する。法令間に依存はないため、Claude Code の並列エージェント等で同時に実施してよい。

1. **URL の列挙** — frontmatter(`eGovUrl` / `officialExplanations[].url`)と本文の出典 URL をすべて列挙する
2. **HTTP 実機確認** — 各 URL を curl で確認する
   - ステータスを記録(200 / 301 / 404)。301 は `Location` の移転先も確認する
   - 検証は curl の生テキスト(必要なら `pdftotext -layout`)による逐語照合で行う。要約ツール経由の確認はしない
3. **現行版の突合(200 でも安心しない)** — 発行元のハブページ(文部科学省・こども家庭庁などの案内ページ)を curl で取得し、現行版の発行年月・版番号・改訂通知の有無を本文から逐語で確認する。ページが参照している版(タイトル・発行年月)と現行版を突合する
4. **判定** — 次のいずれかで報告する
   - **OK**: 現行版を参照している
   - **要更新**: 新版・改訂版が出ている、または URL が移転している
   - **要人間判断**: 複数版が併載されている等、置換可否の判断が必要

### 3. 出口

- **全 URL OK** → `lastVerified` を実施日に更新する PR を起票する(stale-check のリセットに必要)
- **要更新あり** → 現行版への置換 PR を起票する(前例: PR #80・#82)。現行版への更新はユーザー価値があるため changelog 対象
- いずれも issue は PR マージ後にクローズする

### 置換時の注意

- 旧版が公式ハブに併載され続けていても、現行版が明示されていれば現行版へ置換する(PR #80・#82 の前例)
- 新 URL は HTTP ステータスだけでなく Content-Type・タイトル・発行年月を逐語確認してから反映する
- 出典の取得日(`retrievedAt` / 本文の出典行)も実施日に更新する
